Privacy policy

Last updated: September 14, 2026

Finance Hub is a private bookkeeping application maintained by the project operator for the owner and a small number of personally invited users. This policy describes the current collector and transaction-extraction tools.

Information accessed

  • Google account identity: the connected email address, used to confirm the intended mailbox.
  • Gmail: message and thread identifiers, sender and recipient headers, subjects, dates, message bodies, original email content, and attachments for messages retrieved by the configured collection searches. Financial messages may contain account identifiers, transaction amounts, merchant names, loan information, or other personal details. A matching message may also include nonfinancial content.
  • Google Drive: folder and file identifiers, names, metadata, and file contents needed to save and verify originals and restore processing state.
  • Derived records: extracted transaction candidates, content hashes, processing status, discovery information, retry records, and checkpoints.
  • Authorization credentials: OAuth tokens used to access authorized Google services. The application does not collect your Google password.

Permissions and their purpose

gmail.readonly permits reading the authorized mailbox. Searches select messages for collection, but the permission itself is not limited to those messages. The current collector does not send, delete, archive, or label Gmail messages.

drive grants broad access to Google Drive, including capabilities beyond the current collector's use. It is not a folder-restricted permission. The application uses configured folders to read, create, verify, and restore archive and state files, including existing records. The current collector does not delete files or alter their sharing settings.

How information is used

Information is used to preserve source records, prevent duplicate collection, recover interrupted processing, and prepare transaction candidates for bookkeeping review. Records support the user's budgeting and tax-preparation work. The current collector does not send financial emails to an AI model. Google user data is not used for advertising, sold to data brokers, used for lending decisions, or used to train generalized AI or machine-learning models.

Storage and service providers

Original emails and attachments are stored in designated Google Drive folders. A separate Drive system-state folder holds database snapshots and supporting recovery copies, which may also contain personal or financial information.

When a workflow runs in GitHub Actions, Google data is downloaded and processed temporarily on a GitHub-hosted runner. The workflow is configured to remove its working directory after the run. A local run instead uses storage on the operator's computer, where copies remain until removed. OAuth credentials for hosted runs are stored in GitHub Actions secrets; local runs use private runtime configuration.

Google provides account authorization and Drive storage; GitHub provides hosted workflow execution and this public information site. Their services process information needed to deliver those functions under their respective policies: Google Privacy Policy and GitHub Privacy Statement.

Financial records and tokens are not intentionally published in source code, public pages, workflow logs, or downloadable CI artifacts. Runtime logs are designed to report counts, status, and sanitized errors.

Access and disclosure

Access depends on the permissions of the connected accounts, Drive folders, local computer, and GitHub project. The operator reviews another user's specific messages or documents only with that user's affirmative permission, except where needed for security or legal obligations. Additional disclosure occurs only with the user's authorization to provide the bookkeeping service, for necessary security purposes, or as required by law. This app does not automatically share records with an accountant or other outside recipient.

Retention and deletion

There is currently no automatic retention period or cleanup schedule for originals, local copies, or Drive snapshots. Records remain until the user or operator removes them. Recovery snapshots may retain copies even after an individual archived document is deleted.

To request deletion, contact the operator below. Deletion must cover the relevant originals, derived records, supporting recovery files, snapshots, and any local copies; deleting only the visible receipt is not sufficient. The operator will coordinate the scope with the account owner. Provider backups and operational records may follow the provider's own retention policies.

Revoke access or stop collection

You can remove Finance Hub's authorization through your Google Account connections. You can also ask the operator to stop collection and remove stored credentials. Revoking authorization stops future authorized access but does not automatically delete previously saved information.

Security

The collector uses HTTPS for Google API requests, verifies archived file content with hashes, and separates credentials from source code. Folder permissions, GitHub access controls, and local-device security remain important. No storage or transmission method can guarantee complete security.

This public website

These pages contain no analytics scripts, advertising, tracking pixels, contact forms, or application login. The pages themselves do not set cookies. GitHub Pages may process technical visitor information, such as IP addresses, to provide and secure its hosting service.

Google API Limited Use

Finance Hub's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Changes and contact

This policy will be updated before materially different data practices are introduced. Affected users will be notified and asked for additional consent where required.

For privacy questions, access assistance, or deletion requests, contact the project operator at ajitsinghsethi@gmail.com. Do not include passwords, tokens, or full financial account numbers in your request.
